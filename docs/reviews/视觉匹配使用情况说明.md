# 视觉匹配使用情况说明

**检查时间**: 2026-01-14  
**状态**: ⚠️ 已集成但覆盖率低

## 一、当前状态

### 1.1 代码集成情况

✅ **已集成Gemini Flash Vision API**:
- 文件: `src/abu/ai_vision_matcher.py`
- 模型: `google/gemini-2.5-flash-image`
- 功能: 比较模式库图片和实时图表图片的相似度

✅ **已集成到交易计划生成**:
- 文件: `scripts/generate_vision_enhanced_trading_plan.py`
- 在匹配到模式后，如果模式有图片，会进行视觉匹配

### 1.2 实际使用情况

❌ **覆盖率极低**:
- 有图片的模式: **3/7229** (0.04%)
- Gemini Flash: 3/429 个有图片
- Cursor AI: 0/23 个有图片
- Brooks规则: 0/6777 个有图片

**结论**: 虽然代码已集成，但**实际几乎不会触发视觉匹配**，因为99.96%的模式没有图片。

## 二、视觉匹配流程

### 2.1 当前实现流程

```
1. 模式匹配（算法）→ 找到最佳匹配
2. 检查匹配的模式是否有图片
   ├─ 有图片 → 调用Gemini Vision API进行视觉匹配
   └─ 无图片 → 跳过视觉匹配，只使用算法匹配结果
3. 结合算法匹配分数和视觉匹配分数
```

### 2.2 视觉匹配代码位置

```python
# scripts/generate_vision_enhanced_trading_plan.py (第252-262行)
# 视觉匹配（如果模式有图片）
vision_score = None
if best_match.pattern and hasattr(best_match.pattern, 'image_path') and best_match.pattern.image_path:
    pattern_image_path = Path(best_match.pattern.image_path)
    if pattern_image_path.exists():
        vision_result = vision_matcher.compare_two_images(
            pattern_image_path,  # 模式库图片
            chart_image_path,    # 实时图表图片
            context=f"{symbol} {timeframe} chart"
        )
        vision_score = vision_result.similarity_score / 100.0
```

## 三、问题分析

### 3.1 为什么覆盖率低？

1. **Gemini Flash模式**: 只有3个有图片路径
   - 可能原因：数据库中的`image_path`字段大部分为空
   - 需要检查：`pattern_library`表的`image_path`字段

2. **Cursor AI模式**: 0个有图片
   - 可能原因：Cursor AI模式来自识别结果，没有关联图片

3. **Brooks规则**: 0个有图片
   - 可能原因：Brooks规则来自电子书文本，没有图片

### 3.2 如何提高覆盖率？

**方案1: 补充模式库图片路径**
```sql
-- 检查pattern_library表的image_path字段
SELECT COUNT(*) FROM pattern_library WHERE image_path IS NOT NULL AND image_path != '';
```

**方案2: 使用Gemini Vision直接分析实时图表**
- 不使用模式库图片对比
- 直接让Gemini Vision分析实时图表，识别模式
- 然后与模式库的特征描述匹配

**方案3: 为所有模式生成图片**
- 从PDF提取所有图片
- 关联到对应的模式记录
