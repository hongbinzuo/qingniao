# ABU系统v3.0回测框架使用说明

**版本**: v3.0  
**完成时间**: 2026-01-14  
**状态**: ✅ 已完成

## 一、回测框架概述

### 1.1 设计理念

借鉴nofx回测框架的设计，实现了一个完善的Python回测引擎，支持：

- ✅ **账户管理**: 资金、仓位、手续费、滑点
- ✅ **保本止损**: 触及止盈1后移动止损到入场价
- ✅ **性能指标**: 总收益率、最大回撤、Sharpe比率、盈亏比、胜率等
- ✅ **权益曲线**: 记录每个时间点的权益变化
- ✅ **交易事件**: 记录所有开仓和平仓事件
- ✅ **信号验证**: 自动检查止损方向等低级错误

### 1.2 与nofx框架的对比

| 特性 | nofx (Go) | ABU v3.0 (Python) | 状态 |
|------|-----------|-------------------|------|
| 账户管理 | ✅ | ✅ | 已实现 |
| 手续费/滑点 | ✅ | ✅ | 已实现 |
| 权益曲线 | ✅ | ✅ | 已实现 |
| 性能指标 | ✅ | ✅ | 已实现 |
| 检查点保存 | ✅ | ⚠️ | 部分实现 |
| 断点续传 | ✅ | ⚠️ | 部分实现 |
| 多币种支持 | ✅ | ⚠️ | 当前仅BTC |
| 杠杆交易 | ✅ | ❌ | 未实现（可扩展）|

**结论**: 核心功能已完善，可以满足交易计划回测需求。

## 二、文件结构

### 2.1 核心文件

- **`src/abu/backtest_engine.py`**: 回测引擎核心
  - `BacktestAccount`: 账户管理
  - `BacktestEngine`: 回测引擎
  - `BacktestMetrics`: 性能指标
  - `EquityPoint`: 权益点
  - `TradeEvent`: 交易事件

- **`scripts/backtest_trading_plan.py`**: 单文件回测脚本
  - 从Markdown文件解析信号
  - 执行回测
  - 生成报告

- **`scripts/auto_backtest_trading_plans.py`**: 自动化回测脚本
  - 批量扫描交易计划文件
  - 自动回测所有计划
  - 生成汇总报告

## 三、使用方法

### 3.1 回测单个交易计划文件

```bash
# 基本用法
python scripts/backtest_trading_plan.py trading_signals/vision_enhanced_plan_20260114_110937.md

# 自定义参数
python scripts/backtest_trading_plan.py trading_signals/vision_enhanced_plan_20260114_110937.md \
    --initial-balance 20000 \
    --fee-bps 5 \
    --slippage-bps 2 \
    --position-size 0.15 \
    --output trading_signals/backtest_report_custom.md
```

**参数说明**:
- `--initial-balance`: 初始资金（默认10000 USDT）
- `--fee-bps`: 手续费基点（默认5，即0.05%）
- `--slippage-bps`: 滑点基点（默认2，即0.02%）
- `--position-size`: 单笔仓位百分比（默认0.1，即10%）
- `--output`: 输出报告文件路径（可选）

**输出**:
- Markdown报告: `trading_signals/backtest_report_*.md`
- 包含性能指标和每个信号的详细结果

### 3.2 自动化批量回测

```bash
# 回测所有交易计划文件
python scripts/auto_backtest_trading_plans.py

# 限制回测文件数量
python scripts/auto_backtest_trading_plans.py --limit 5

# 自定义参数
python scripts/auto_backtest_trading_plans.py \
    --initial-balance 20000 \
    --fee-bps 5 \
    --slippage-bps 2 \
    --position-size 0.15 \
    --plans-dir trading_signals \
    --output-dir trading_signals/backtest_reports
```

**功能**:
- 自动扫描 `trading_signals/` 目录下的所有交易计划文件
- 支持的文件模式:
  - `*trading_plan*.md`
  - `*vision_enhanced*.md`
  - `*ABU_v3*.md`
- 为每个文件生成独立的回测报告
- 生成汇总报告

**输出**:
- 每个计划的报告: `trading_signals/backtest_reports/backtest_*.md`
- JSON结果: `trading_signals/backtest_reports/backtest_*.json`
- 汇总报告: `trading_signals/backtest_reports/backtest_summary_*.md`

### 3.3 在代码中使用回测引擎

```python
from abu.backtest_engine import BacktestEngine

# 初始化引擎
engine = BacktestEngine(
    initial_balance=10000.0,
    fee_bps=5.0,
    slippage_bps=2.0,
    position_size_pct=0.1,
    use_breakeven_stop=True
)

# 回测信号
signal = {
    'pattern_id': 'signal_001',
    'pattern_name': 'Wedge Bottom',
    'pattern_type': 'Wedge',
    'source': 'gemini_flash',
    'direction': 'long',
    'entry_price': 95509.80,
    'stop_loss': 92025.40,
    'take_profit_1': 100736.40,
    'take_profit_2': 104220.80,
    'confidence': 0.98
}

result = engine.backtest_signal(signal, timeframe='5m')

# 计算指标
metrics = engine.calculate_metrics()

# 清理
engine.close()
```

## 四、回测逻辑说明

### 4.1 保本止损逻辑

1. **初始状态**: 使用信号中的止损价
2. **触及止盈1**: 止损移动到入场价（保本）
3. **触及保本止损**: 状态为"部分止盈"（`partial_tp`），不是"止损"（`stopped`）

### 4.2 信号验证

回测引擎会自动验证：
- ✅ 做多止损应在入场价下方
- ✅ 做空止损应在入场价上方
- ✅ 入场价未到但先到止盈1，信号无效

### 4.3 价格数据

- 使用时序数据库: `data/btc_price_timeseries.duckdb`
- 支持时间框架: 5m, 15m, 1h, 4h, 1d
- 自动获取信号时间之后的价格数据

### 4.4 账户管理

- **手续费**: 开仓和平仓各收取一次（默认0.05%）
- **滑点**: 买入时价格更高，卖出时价格更低（默认0.02%）
- **仓位**: 单笔仓位为总权益的固定百分比（默认10%）
- **资金检查**: 开仓前检查资金是否足够

## 五、性能指标说明

### 5.1 基础指标

- **总收益率**: `(最终权益 - 初始资金) / 初始资金 * 100`
- **最大回撤**: 权益曲线从最高点到最低点的最大跌幅
- **胜率**: `盈利交易数 / 总交易数 * 100`
- **盈亏比**: `总盈利 / 总亏损`

### 5.2 风险调整指标

- **Sharpe比率**: `平均收益率 / 收益率标准差`
  - 衡量风险调整后的收益
  - 通常>1.0表示良好

- **Profit Factor**: `总盈利 / 总亏损`
  - >1.0表示盈利大于亏损
  - 通常>1.5表示良好

### 5.3 交易统计

- **总交易数**: 完成的交易数量
- **盈利交易数**: 盈利的交易数量
- **亏损交易数**: 亏损的交易数量
- **平均盈利**: 盈利交易的平均盈利金额
- **平均亏损**: 亏损交易的平均亏损金额

## 六、自动化方案

### 6.1 定时任务（Windows）

创建 `scripts/auto_backtest_daily.bat`:

```batch
@echo off
cd /d C:\Users\zuoho\code\qingniao
python scripts/auto_backtest_trading_plans.py
pause
```

使用Windows任务计划程序：
1. 打开"任务计划程序"
2. 创建基本任务
3. 触发器：每天指定时间
4. 操作：启动程序 `scripts/auto_backtest_daily.bat`

### 6.2 定时任务（Linux/macOS）

创建 `scripts/auto_backtest_daily.sh`:

```bash
#!/bin/bash
cd /path/to/qingniao
python3 scripts/auto_backtest_trading_plans.py >> logs/backtest.log 2>&1
```

添加到crontab:
```bash
# 每天凌晨2点执行
0 2 * * * /path/to/qingniao/scripts/auto_backtest_daily.sh
```

### 6.3 集成到交易计划生成流程

修改 `scripts/generate_vision_enhanced_trading_plan.py`，在生成计划后自动回测：

```python

if all_plans:

        plans_dir=ROOT / 'trading_signals',
```

## 八、注意事项

### 8.1 价格数据

- 确保价格数据已同步到数据库
- 运行 `python src/sync_btc_prices_daily.py` 同步最新数据

### 8.2 信号格式

交易计划Markdown文件需要包含以下字段：
- 入场价 (`- **入场价**:`)
- 止损价 (`- **止损价**:`)
- 止盈1 (`- **止盈1**:`)
- 方向 (`- **方向**:`)

### 8.3 回测限制

- 当前仅支持BTC（可扩展）
- 不支持杠杆交易（可扩展）
- 不支持多币种同时持仓（可扩展）
