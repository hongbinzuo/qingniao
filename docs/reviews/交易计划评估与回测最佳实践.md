## 一、交易计划评估框架

### 1.1 三层验证体系

#### 第一层：生成时验证（实时）
- ✅ **Brooks规则验证器** - 自动检测严重错误
- ✅ **基础参数验证** - 止损方向、价格合理性
- ✅ **模式-方向一致性** - 确保顺势交易

**优势**: 立即发现问题，避免生成无效信号

#### 第二层：回测前验证（批量）
- ✅ **批量Brooks验证** - 统计验证通过率
- ✅ **数据完整性检查** - 确保有价格数据
- ✅ **参数合理性检查** - 止损距离、盈亏比

**优势**: 过滤不可交易信号，节省回测资源

#### 第三层：回测后评估（结果分析）
- ✅ **性能指标分析** - 收益率、胜率、Sharpe比率
- ✅ **风险指标分析** - 最大回撤、风险调整收益
- ✅ **交易质量分析** - 平均盈亏比、连续亏损

**优势**: 全面评估策略有效性

## 二、关键评估指标

### 2.1 必须检查的指标（Critical）

#### 1. 止损位置正确性
```python
# 做多：止损 < 入场价
# 做空：止损 > 入场价
# 止损距离：5分钟≥1.5%，15分钟≥2%
```

**检查点**:
- ✅ 止损方向正确
- ✅ 止损不等于入场价
- ✅ 止损距离符合时间框架要求

#### 2. 盈亏比（Risk-Reward Ratio）
```python
# 最低要求：2:1
# 理想目标：3:1
# 严重错误：< 1:1
```

**检查点**:
- ✅ 盈亏比 ≥ 2:1
- ✅ 风险可计算（风险 > 0）
- ✅ 止盈目标合理（不超过20%）

#### 3. 顺势交易一致性
```python
# Bull模式 → 必须做多
# Bear模式 → 必须做空
# 上升通道 → 必须做多
# 下降通道 → 必须做空
```

**检查点**:
- ✅ 模式类型与交易方向一致
- ✅ 无逆势交易信号

### 2.2 重要评估指标（Important）

#### 1. 回测胜率（Win Rate）
```python
# 最低要求：≥ 40%
# 理想目标：≥ 50%
# 优秀表现：≥ 60%
```

**评估标准**:
- 🚨 < 30%: 严重问题，策略无效
- ⚠️ 30-40%: 需要改进
- ✅ 40-50%: 可接受
- ✅ > 50%: 优秀

#### 2. 总收益率（Total Return）
```python
# 考虑：
# - 绝对收益率
# - 年化收益率
# - 风险调整收益率
```

**评估标准**:
- 结合胜率和盈亏比评估
- 单次回测收益率应 > 0%
- 长期应保持正收益

#### 3. 最大回撤（Max Drawdown）
```python
# 最大回撤 = (峰值权益 - 最低权益) / 峰值权益
# 建议：< 20%
```

**评估标准**:
- 🚨 > 30%: 风险过高
- ⚠️ 20-30%: 需要控制风险
- ✅ < 20%: 可接受
- ✅ < 10%: 优秀

#### 4. Sharpe比率（Sharpe Ratio）
```python
# Sharpe = (收益率 - 无风险利率) / 收益率标准差
# 建议：≥ 0.5
```

**评估标准**:
- 🚨 < 0: 风险调整后收益为负
- ⚠️ 0-0.5: 需要改进
- ✅ 0.5-1.0: 可接受
- ✅ > 1.0: 优秀

#### 5. 盈亏比（Profit Factor）
```python
# 盈亏比 = 总盈利 / 总亏损
# 建议：≥ 1.2
```

**评估标准**:
- 🚨 < 1.0: 总亏损 > 总盈利
- ⚠️ 1.0-1.2: 需要改进
- ✅ 1.2-2.0: 可接受
- ✅ > 2.0: 优秀

### 2.3 辅助评估指标（Supporting）

#### 1. 平均盈利 vs 平均亏损
```python
# 平均盈利应 > 平均亏损
# 理想：平均盈利 ≥ 2 × 平均亏损
```

#### 2. 连续亏损次数
```python
# 最大连续亏损 ≤ 5次
# 如果 > 5次，需要检查策略
```

#### 3. 交易频率
```python
# 评估信号生成频率
# 过多信号：可能过度交易
# 过少信号：可能错过机会
```

## 三、回测评估流程

### 3.1 回测前检查清单

```
□ 1. 价格数据完整性
   - 检查是否有足够的历史数据
   - 检查数据时间范围是否覆盖回测期间
   
□ 2. 信号参数完整性
   - 入场价、止损、止盈都有值
   - 方向明确（long/short）
   - 时间框架正确
   
□ 3. Brooks规则验证
   - 止损位置正确
   - 盈亏比 ≥ 2:1
   - 无逆势交易
   - 无稳定币不合理信号
   
□ 4. 数据质量检查
   - 无异常价格（如0、负数）
   - 价格变化合理（无跳空过大）
```

### 3.2 回测执行

```python
# 1. 初始化回测引擎
engine = BacktestEngine(
    initial_balance=10000.0,
    fee_bps=5.0,  # 0.05%手续费
    slippage_bps=2.0,  # 0.02%滑点
    position_size_pct=0.1  # 10%仓位
)

# 2. 回测每个信号
for signal in signals:
    result = engine.backtest_signal(
        signal, 
        timeframe=signal['timeframe'],
        validate_brooks_rules=True  # 启用Brooks验证
    )

# 3. 计算性能指标
metrics = engine.calculate_metrics()
```

### 3.3 回测后分析

#### 1. 性能指标分析
```python
# 必须检查的指标
- 总收益率: metrics.total_return_pct
- 胜率: metrics.win_rate
- 最大回撤: metrics.max_drawdown_pct
- Sharpe比率: metrics.sharpe_ratio
- 盈亏比: metrics.profit_factor
```

#### 2. 问题识别
```python
# 自动检测问题
if metrics.win_rate < 0.4:
    issues.append("胜率过低")
    
if metrics.profit_factor < 1.2:
    issues.append("盈亏比不足")
    
if metrics.max_drawdown_pct > 0.2:
    issues.append("最大回撤过大")
```

#### 3. 信号质量分析
```python
# 分析每个信号的表现
- 哪些信号盈利？
- 哪些信号亏损？
- 亏损信号的原因？
- 是否有共同特征？
```

## 五、实践建议

### 5.1 日常评估流程

#### 每日评估
1. **生成交易计划** → 自动Brooks验证
2. **自动回测** → 获取性能指标
3. **问题反馈** → 识别严重问题
4. **记录结果** → 保存回测报告

#### 每周评估
1. **汇总周度表现** → 统计胜率、收益率
2. **识别问题模式** → 分析失败信号
3. **优化策略** → 调整参数或规则
4. **更新文档** → 记录改进措施

#### 每月评估
1. **全面性能分析** → 多维度评估
2. **策略对比** → 不同方法对比
3. **参数优化** → 寻找最优参数
4. **系统改进** → 基于数据改进

#### 信号质量评分

#### 策略有效性评分
```python
# 总分100分
```

### 5.3 问题处理流程

#### 严重问题（Critical）
```
1. 立即停止使用该信号
2. 分析问题原因
3. 修复生成逻辑
4. 重新生成并验证
```

#### 一般问题（Error）
```
1. 标记问题信号
2. 分析问题模式
3. 优化生成逻辑
4. 监控改进效果
```

#### 警告（Warning）
```
1. 记录警告信息
2. 持续监控
3. 必要时优化
```
