# PDF完整处理流程方案（9000+图片）

## 概述

处理包含约9000张图片的PDF交易教材，提取图表模式和交易策略文字说明。

## 完整流程架构

```
┌─────────────────────────────────────────────────────────────┐
│ 步骤1: PDF转图片（不使用Gemini）                              │
│ 工具: PyMuPDF (本地，快速免费)                                │
│ 输出: 9000+ PNG图片 → data/abu/images/                       │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤2: 图表识别与提取                                         │
│ 工具: PyMuPDF + 图像处理算法                                  │
│ 输出: pattern_library 表（图表元数据）                        │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤3: 模式分类                                               │
│ 工具: LLaVA 或 Gemini Vision（分类图表类型）                  │
│ 输出: pattern_type 字段（Triangle, HeadAndShoulders等）      │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤4: 文字提取（使用Gemini Vision API）                      │
│ 工具: OpenRouter + Gemini 2.5 Flash Image                    │
│ 输出: chart_features_json.vision_text（交易策略文字）        │
│ 成本: ~$9 USD (9000张 × $0.001)                              │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤5: 模式库完成                                             │
│ 输出: 完整的模式库（图形+分类+文字说明）                      │
│ 用途: 实时图表匹配、交易信号生成                              │
└─────────────────────────────────────────────────────────────┘
```

## 各步骤详细说明

### 步骤1: PDF转图片 ✅ 不使用Gemini

**工具**: PyMuPDF (fitz)
**位置**: `scripts/pa_ingest_pdf.py`

**为什么不用Gemini？**
- ✅ PDF转图片是纯技术操作，不需要AI理解
- ✅ PyMuPDF是本地工具，速度快、免费、可靠
- ✅ 可以精确提取图片位置、尺寸等元数据

**功能**：
- 提取PDF中的所有图片
- 保存为PNG格式到 `data/abu/images/`
- 记录图片位置信息到 `raw_pages.jsonl`
- 处理约9000张图片，预计耗时：10-30分钟

**使用方式**：
```python
from scripts.pa_ingest_pdf import extract

# 提取PDF图片（不使用Gemini）
extract(
    pdf_path='data/abu/book.pdf',
    out_path='data/abu/raw_pages.jsonl',
    images_dir='data/abu/images/',
    max_pages=None  # 处理所有页面
)
```

**输出示例**：
```
data/abu/images/
  ├── page_0001_img_01_x1234_abcd1234.png
  ├── page_0001_img_02_x1235_efgh5678.png
  ├── ...
  └── page_1000_img_01_x9999_xxxx9999.png
```

---

### 步骤2: 图表识别与提取 ✅ 不使用Gemini

**工具**: 图像处理算法 + PyMuPDF
**位置**: `scripts/abu/abu_build_library.py`（或类似脚本）

**为什么不用Gemini？**
- ✅ 图表提取是结构化操作，可以用算法完成
- ✅ 基于图片位置、尺寸等元数据提取
- ✅ 快速、准确、免费

**功能**：
- 从 `raw_pages.jsonl` 读取图片信息
- 识别图表区域（基于尺寸、位置等规则）
- 保存图表到数据库 `pattern_library` 表
- 记录图表元数据（页面号、位置、尺寸等）

**使用方式**：
```bash
python scripts/abu/abu_complete_pipeline.py --skip step1,step3,step4 --pdf book.pdf
```

**输出**：
- `pattern_library` 表包含约9000条记录
- 每条记录包含：`id, image_path, page_number, bbox` 等

---

### 步骤3: 模式分类 ✅ 可选使用Gemini

**工具**: LLaVA 或 Gemini Vision（用于分类）
**位置**: `scripts/abu/abu_llava_classify_patterns.py` 或类似

**可选方案**：
- **方案A**: 使用 LLaVA（本地，免费但需要GPU）
- **方案B**: 使用 Gemini Vision API（准确率高，需要成本）

**为什么分类需要AI？**
- ✅ 需要理解图表形态（三角形、头肩顶等）
- ✅ 需要识别图表特征
- ✅ AI分类准确率比规则高

**使用方式（Gemini）**：
```bash
python scripts/abu/abu_gemini_classify_patterns.py --limit 1000 --model google/gemini-2.5-flash-image
```

**输出**：
- 更新 `pattern_library.pattern_type` 字段
- 分类结果：Triangle, HeadAndShoulders, InsideBar 等

---

### 步骤4: 文字提取 ✅ **使用Gemini Vision API**

**工具**: OpenRouter + Gemini 2.5 Flash Image
**位置**: `scripts/extract_pattern_text_openrouter.py`

**为什么必须用Gemini Vision？**
- ✅ 文字在图片中，需要OCR识别
- ✅ 需要理解交易策略语义
- ✅ 准确率高（90-95%）
- ✅ 能提取结构化信息（模式名称、方向、概率等）

**处理策略（9000张图片）**：

#### 方案A: 分批处理（推荐）

```bash
# 第一批：测试100张
python scripts/extract_pattern_text_openrouter.py --limit 100 --model google/gemini-2.5-flash-image

# 第二批：处理1000张（估算成本 $1）
python scripts/extract_pattern_text_openrouter.py --limit 1000 --model google/gemini-2.5-flash-image --sleep-ms 1000

# 第三批：处理剩余图片（根据实际情况继续）
python scripts/extract_pattern_text_openrouter.py --limit 2000 --model google/gemini-2.5-flash-image --sleep-ms 1000

# ... 重复直到处理完所有图片
```

#### 方案B: 使用完整流程脚本

```bash
# 只执行步骤4（文字提取），其他步骤已完成
python scripts/abu/abu_complete_pipeline.py \
    --skip step1,step2,step3 \
    --ocr-limit 1000 \
    --use-vision
```

**成本估算**：
```
9000 张图片 × $0.001/张 = $9 USD

建议分批处理：
- 第一批：100张 ($0.10) - 测试
- 第二批：1000张 ($1.00) - 验证
- 后续：8000张 ($8.00) - 批量处理
```

**时间估算**：
```
单张图片处理时间：~3秒（API调用 + 数据库更新）
延迟：1秒（控制API频率）
总时间：9000 × (3 + 1) = 36000秒 ≈ 10小时

建议：
- 分批运行，避免一次性处理
- 可以后台运行，监控进度
```

**输出**：
- 更新 `pattern_library.chart_features_json.vision_text` 字段
- 包含交易策略文字说明，例如：
  ```json
  {
    "vision_text": "Gap bar buy in small PB bull trend so 75% chance of test of high of day",
    "vision_model": "google/gemini-2.5-flash-image",
    "vision_extracted_at": "2026-01-10 12:00:00"
  }
  ```

## 技术选择总结

| 步骤 | 任务 | 使用技术 | 为什么 | 成本 |
|------|------|---------|--------|------|
| **步骤1** | PDF转图片 | **PyMuPDF**（本地） | 纯技术操作，不需要AI | 免费 |
| **步骤2** | 图表提取 | **算法**（PyMuPDF） | 结构化操作，算法足够 | 免费 |
| **步骤3** | 模式分类 | **LLaVA/Gemini**（可选） | 需要理解图表形态 | 可选 |
| **步骤4** | 文字提取 | **Gemini Vision API** | 需要OCR+语义理解 | ~$9 |
| **步骤5** | 实时图表匹配 | **算法**（不使用Gemini） | 结构化数据，算法足够 | 免费 |

## 完整执行命令

### 方案1: 一次性完整流程（适合首次处理）

```bash
# 完整流程（处理全部9000张图片）
python scripts/abu/abu_complete_pipeline.py \
    --pdf data/abu/book.pdf \
    --use-vision \
    --ocr-limit 9000
```

### 方案2: 分步骤执行（推荐，便于监控和调试）

```bash
# 步骤1: PDF转图片（不使用Gemini）
python scripts/abu/abu_complete_pipeline.py \
    --pdf data/abu/book.pdf \
    --skip step2,step3,step4

# 步骤2: 图表提取（不使用Gemini）
python scripts/abu/abu_complete_pipeline.py \
    --skip step1,step3,step4

# 步骤3: 模式分类（可选，使用Gemini）
python scripts/abu/abu_gemini_classify_patterns.py \
    --limit 9000 \
    --model google/gemini-2.5-flash-image

# 步骤4: 文字提取（使用Gemini Vision API，分批处理）
python scripts/extract_pattern_text_openrouter.py \
    --limit 1000 \
    --model google/gemini-2.5-flash-image \
    --sleep-ms 1000

# 重复步骤4，直到处理完所有图片
```

### 方案3: 只处理新图片（增量处理）

```bash
# 如果之前已处理部分图片，只处理新的
python scripts/extract_pattern_text_openrouter.py \
    --limit 1000 \
    --model google/gemini-2.5-flash-image \
    --sleep-ms 1000
    # 自动跳过已有 vision_text 的记录
```

## 注意事项

1. **API调用频率控制**
   - 使用 `--sleep-ms 1000` 控制调用频率
   - 避免触发API限制

2. **错误处理**
   - 脚本会自动跳过失败记录
   - 可以使用 `--force` 重新处理失败的记录

3. **成本控制**
   - 先小批量测试（100张）
   - 验证效果后再批量处理
   - 监控OpenRouter控制台的使用情况
