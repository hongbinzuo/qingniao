# 信号状态追踪功能说明

## 功能概述

系统现在支持对每个生成的交易信号进行状态追踪，每4小时运行时除了生成新信号，还会：
1. 获取最新价格数据
2. 判断之前所有信号的状态
3. 更新信号状态并生成状态报告

## 信号状态类型

1. **pending（挂单中）**：信号已生成，价格尚未接近入场价（距离入场价>1%）
2. **active（交易中）**：价格已接近入场价（距离入场价<1%），或已标记为入场，但未触及止损/止盈
3. **partial_tp（部分止盈）**：已触及第一止盈位，但未触及第二止盈位
4. **stopped（已止损）**：价格触及止损位
5. **full_tp（全部止盈）**：价格触及第二止盈位（全部止盈）

## 实现细节

### 1. 信号追踪模块

**文件**: `src/signal_tracker.py`

**主要功能**:
- `SignalTracker`类：管理信号存储和状态更新
- `add_signal()`：添加新信号到追踪列表
- `update_signal_status()`：根据最新价格更新所有信号状态
- `format_signal_status_report()`：生成状态报告

**数据存储**:
- 信号数据保存在 `trading_signals/.signal_history/signals.json`
- JSON格式，按系统分类存储

### 2. 状态判断逻辑

**入场判断**:
- 如果价格接近入场价（距离<1%），自动标记为已入场
- 记录入场时间

**止损判断**:
- 做多：当前价格 <= 止损价
- 做空：当前价格 >= 止损价

**止盈判断**:
- 第一止盈：价格触及take_profit_1
- 第二止盈：价格触及take_profit_2（全部止盈）

**浮盈浮亏计算**:
- 实时计算当前浮盈浮亏百分比
- 记录最大浮盈和最大浮亏

### 3. 整合到统一系统

**修改文件**: `src/unified_trading_system.py`

**主要改动**:
1. 在`__init__`中初始化`SignalTracker`
2. 在`run_de_system`中提取信号并添加到追踪器
3. 在`run_all_systems`中：
   - 首先更新所有历史信号状态
   - 生成新信号
   - 将状态报告追加到最新生成的文件中

**信号提取**:
- 从`generate_btc_de_signals`模块的`_last_analysis_result`全局变量中提取
- 每个时间框架（5分钟、15分钟）选择最强的信号进行追踪

### 4. 状态报告格式

报告包含以下部分：

1. **统计信息**：各状态信号数量
2. **挂单中**：等待入场价的信号
3. **交易中**：已入场，显示当前浮盈浮亏
4. **部分止盈**：已触及第一止盈位
5. **已止损（最近5个）**：显示最大浮亏
6. **全部止盈（最近5个）**：显示最大浮盈

## 使用方式

### 自动运行（每4小时）

```bash
python src/unified_trading_system.py --system all --interval 4
```

系统会自动：
1. 更新所有历史信号状态
2. 生成新的交易信号
3. 将状态报告追加到最新生成的文件中

### 查看信号状态

信号数据保存在：`trading_signals/.signal_history/signals.json`

可以手动查看或使用Python脚本：

```python
from src.signal_tracker import SignalTracker
tracker = SignalTracker()
signals_data = tracker.load_signals()
# 查看所有信号
```

## 注意事项

1. **价格数据来源**：使用De.系统的`get_btc_current_price()`获取最新价格
2. **信号提取**：目前只支持De.系统的信号追踪，梦多空策略的追踪待实现
3. **状态判断**：基于价格触及逻辑，实际交易中可能需要考虑滑点等因素
4. **数据持久化**：信号数据保存在JSON文件中，可以手动备份

## 下一步改进

1. **支持梦多空策略信号追踪**：从梦多空策略生成的报告中提取信号
2. **更精确的入场判断**：考虑订单簿数据，判断是否真正入场
3. **信号过滤**：超过一定时间未入场的信号自动标记为过期
4. **统计分析**：提供信号胜率、平均盈亏等统计信息
