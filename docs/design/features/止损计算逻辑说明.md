# 实时订单簿止损计算逻辑说明

## 核心原理

**不是固定百分比！** 而是基于实时订单簿的流动性分析：

### 1. 流动性分析

1. **价格聚合**：将订单簿中的价格聚合到整数档位（BTC以100为单位）
2. **识别密集区**：挂单量 > 平均挂单量 × 1.5倍 → 流动性密集区（支撑/阻力位）
3. **识别稀疏区**：挂单量 < 平均挂单量 × 0.5倍 → 流动性稀疏区（适合止损）

### 2. 做多止损逻辑

**目标**：止损放在买单密集区（支撑位）下方，但在流动性稀疏区

**步骤**：
1. 找到入场价下方的买单密集区（支撑位）
2. 在支撑位下方找流动性稀疏区
3. 如果有稀疏区 → 使用稀疏区的价格作为止损（**不是固定百分比！**）
4. 如果没有稀疏区 → 在支撑位下方，根据支撑位的挂单量强度调整距离：
   - 强支撑（挂单量大）→ 更近（0.2%）
   - 弱支撑（挂单量小）→ 更远（0.5%）

### 3. 备用方案

如果找不到密集区：
1. 找到入场价下方挂单量最大的价位作为支撑
2. 在支撑位下方设置止损（基于实际订单簿价格，不是固定百分比）

## 关键点

✅ **基于订单簿实际价格**：止损价格来自订单簿中的实际挂单价格  
✅ **基于流动性分析**：识别密集区和稀疏区  
✅ **动态调整**：根据支撑位强度调整距离  
❌ **不是固定百分比**：虽然可能看起来像百分比，但实际是基于订单簿价格计算

## 示例

假设订单簿分析结果：
- 支撑位：$87,500（挂单量：10 BTC）
- 稀疏区：$87,200（挂单量：0.5 BTC）

止损会设置在：**$87,200**（稀疏区的实际价格），而不是 $87,500 × 0.995

## 为什么看起来像百分比？

在某些情况下，如果：
- 找不到稀疏区
- 需要基于支撑位计算

可能会使用类似百分比的计算，但这是**基于订单簿实际价格和挂单量的动态计算**，不是固定的0.5%或1%。
