## 🎯 建议的版本管理方案

### 1. 分支策略

**主分支**:
- `main` - 生产环境，稳定版本
- `develop` - 开发分支，集成所有功能

**功能分支**:
- `feature/功能名称` - 新功能开发
- `fix/问题描述` - Bug修复
- `database/变更描述` - 数据库相关
- `docs/文档更新` - 文档更新

**发布分支**:
- `release/v版本号` - 发布准备

---

### 2. 提交规范

**格式**: `<type>(<scope>): <subject>`

**类型**:
- `feat` - 新功能
- `fix` - Bug修复
- `docs` - 文档
- `database` - 数据库
- `refactor` - 重构
- `perf` - 性能优化

**示例**:
```bash
feat(database): 实现按交易员分库设计
fix(signals): 修复信号评估计算错误
docs(design): 更新数据库设计文档
database: 迁移现有数据到新结构
```

---

### 3. .gitignore 配置

**已创建增强版**: `.gitignore.enhanced`

**关键排除项**:
- ✅ 数据库文件（`*.duckdb`, `*.db`）
- ✅ 输出文件（`outputs/`, 交易信号文件）
- ✅ 敏感信息（`*.env`, `secrets.json`）
- ✅ 临时文件（`temp/`, `*.tmp`）
- ✅ 编译文件（`__pycache__/`, `target/`）

## 🚀 快速开始

### 方式1: 使用初始化脚本（推荐）

**Windows**:
```bash

```

### 方式2: 手动初始化

```bash
# 1. 初始化Git
git init

# 2. 使用增强版.gitignore（可选）
copy .gitignore.enhanced .gitignore

# 3. 创建develop分支
git checkout -b develop

# 4. 添加文件
git add .

# 5. 首次提交
git commit -m "feat: 初始化青鸟交易系统项目"
```

## ⚠️ 重要提醒

### 不要提交到Git

1. **数据库文件** - 包含敏感数据
2. **输出文件** - 自动生成，不需要版本控制
3. **敏感信息** - API密钥、密码等
4. **临时文件** - 临时数据

### 应该提交

1. **源代码** - 所有Python代码
2. **设计文档** - `docs/design/` 目录
3. **配置文件模板** - `.example` 文件
4. **数据库脚本** - 结构定义和迁移脚本

## 🔄 工作流程示例

### 开发新功能

```bash
# 1. 创建功能分支
git checkout develop
git checkout -b feature/database-v2

# 2. 开发功能
# ... 编写代码 ...

# 3. 提交
git add .
git commit -m "feat(database): 实现按交易员分库"

# 4. 合并到develop
git checkout develop
git merge feature/database-v2
```

### 修复Bug

```bash
# 1. 创建修复分支
git checkout develop
git checkout -b fix/stop-loss-bug

# 2. 修复
# ... 修复代码 ...

# 3. 提交
git add .
git commit -m "fix(signals): 修复止损计算错误"

# 4. 合并
git checkout develop
git merge fix/stop-loss-bug
```
