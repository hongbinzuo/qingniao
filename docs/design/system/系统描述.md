# 系统描述（青鸟·De.交易系统）

## 目标与范围
- 目标：将 De. 的主观交易方法系统化，稳定产出“可执行、可评估、可学习”的 BTC 信号与报告。
- 范围：信号生成（1h/15m/5m）、评估与学习、对话/交易录入、战术指引与情绪/结构判读、守护与状态。

## 总体架构
- 生成层
  - 官方生成器：`src/generate_btc_de_signals.py`（完整版）
  - 风格筛选器：`scripts/generate_style_filtered_signals.py`（简要+详细，RR≥2.0，战术指引/情绪/信心标记）
- 数据层
  - DB：DuckDB（按交易员分库 `src/data/qingniao_de.duckdb`）
  - 表：`trading_signals`、`signal_evaluations`、`trader_viewpoints`、`conversations` 等
- 学习层
  - 评估：`src/evaluate_signal_results.py`（>24h 未评估的信号批评估）
  - 归因：`scripts/label_de_trades_techniques.py`（OTE/动态SR/Vegas/VWAP/883一致性）
  - 摘要：写入 `trading_signals/.learning_reports/`
- 支撑阻力与情绪
  - 动态 SR：`src/sr_detector.py`（swing + 价格网格聚类 + 多周期合并）
  - 情绪聚合：`src/sentiment_aggregator.py`（Fear&Greed、Coinbase 溢价、Binance 多空比、Funding）
- 守护层
  - 定时任务：`scripts/falcon.py`（Windows/Linux；每轮内部开关 DB 连接，避免持锁）
  - 启停：`scripts/falcon_start.bat/.sh`、`scripts/falcon_stop.bat/.sh`
  - 状态：`scripts/falcon_status.py/.bat`（输出 `last_ok/last_errors/last_files`）

## 核心流程
1) 信号生成
   - 每小时由 Falcon 调用风格筛选器与官方生成器
   - 过滤条件：RR≥2.0、只接回踩（排除突破/区间突破）、入场偏差≤0.3%
   - 输出：简要/详细报告；每条信号含“信心标记（A/B/C/D）与线索”
2) 评估与学习
   - 规则：仅评估“未评估且生成时间>24h”的信号
   - 评估结果入库并生成 Markdown 报告；同时更新学习参数与技术归因
3) 录入与归档
   - 对话/交易/截图路径一键录入（批量脚本），落库并写“学习摘要”与“观点”
4) 状态与自愈
   - Falcon 每轮内部创建/关闭 DB 连接，不再长期持锁
   - 失败写入 `last_errors`，文件产出写入 `last_files`

## 战术指引与信心标记
- 战术指引（De.）
  - 以 15m/1h 回撤区 `0.618/0.786` 与“动态 SR”替代固定 883 文本
  - “回撤区 + 未破强阻/强支撑”→ 优先反向；“强穿并回踩不破”→ 翻向
- 信心标记
  - 因素：OTE 命中/邻近、动态 SR 邻近、15m/1h EMA 一致性、形态确认、（后续）情绪加权
  - 输出：A≈68% / B≈58% / C≈50% / D≈45%（可校准）

## 关键模块
- `scripts/generate_style_filtered_signals.py`
  - 产出：`trading_signals/BTC_de_signals_简要_*.md`、`*_full.md`
  - 内容：战术指引、情绪摘要、信心标记、技术分析（Vegas/VWAP/RSI/FVG/OTE/SR/OB）
- `src/sr_detector.py`
  - `detect_levels()`：单时间框架 SR；`merge_multi_tf()`：多周期合并
- `src/sentiment_aggregator.py`
  - `aggregate_sentiment()`：Fear&Greed、Coinbase 溢价、Binance 多空比、Funding，输出情绪分 -100~+100
- `scripts/falcon.py`
  - 周期：默认 1 小时；每轮内开关 DB 连接，`last_errors/last_files` 写入状态
- 录入工具
  - `scripts/record_de_conversation_once.py`、`scripts/record_de_conversations_batch.py`、`scripts/record_de_trade_from_image.py`

## 数据库结构（要点）
- `trading_signals(id, signal_time, timeframe, signal_type, entry_price, stop_loss, take_profit_1, take_profit_2, entry_model, strength, risk_reward_ratio, system_name, status, created_at, updated_at)`
- `signal_evaluations(id, signal_id, evaluation_time, result, actual_entry_price, actual_exit_price, actual_profit_pct, stop_loss_hit, take_profit_1_hit, take_profit_2_hit, missed, notes, created_at)`
- `trader_viewpoints(id, content, timestamp, source, category, tags, btc_price, related_trade_id, related_conversation_id, created_at)`
- `conversations(id, timestamp, user_message, trader_message, source, has_trading_info, extracted_content, btc_price, created_at, ...)`

## 产出目录
- `trading_signals/`：简要/详细信号、评估报告、学习摘要、状态文件
- `docs/design/system/`：系统描述与演进文档

## 运行命令（Windows）
- 启动/停止/状态：
  - `scripts\falcon_start.bat` / `scripts\falcon_stop.bat` / `scripts\falcon_status.bat`
- 录入：
  - 单条对话：`python scripts\record_de_conversation_once.py "01:35" "消息文本"`
  - 批量对话：`python scripts\record_de_conversations_batch.py`
  - 截图交易：`python scripts\record_de_trade_from_image.py`
