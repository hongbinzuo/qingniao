## 🌿 分支策略建议

### 主分支

- **main/master**: 生产环境代码，稳定版本
- **develop**: 开发分支，集成所有功能

### 功能分支

- **feature/功能名称**: 新功能开发
  - 例如: `feature/database-v2`
  - 例如: `feature/ml-scoring`

### 修复分支

- **fix/问题描述**: Bug修复
  - 例如: `fix/stop-loss-calculation`
  - 例如: `fix/database-connection`

### 发布分支

- **release/版本号**: 发布准备
  - 例如: `release/v1.0.0`

### 热修复分支

- **hotfix/问题描述**: 紧急修复
  - 例如: `hotfix/critical-bug`

## 📋 提交规范建议

### 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### Type类型

- **feat**: 新功能
- **fix**: Bug修复
- **docs**: 文档更新
- **style**: 代码格式（不影响功能）
- **refactor**: 重构
- **perf**: 性能优化
- **test**: 测试相关
- **chore**: 构建/工具相关
- **database**: 数据库相关
- **design**: 设计文档

### 示例

```bash
# 新功能
git commit -m "feat(database): 实现按交易员分库设计"

# Bug修复
git commit -m "fix(signals): 修复信号评估计算错误"

# 文档更新
git commit -m "docs(design): 更新数据库设计文档"

# 数据库相关
git commit -m "database: 迁移现有数据到新结构"

# 重构
git commit -m "refactor(de-system): 重构De.交易系统代码"
```

## 🔄 工作流程建议

### 日常开发流程

```bash
# 1. 从develop分支创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/new-feature

# 2. 开发功能
# ... 编写代码 ...

# 3. 提交更改
git add .
git commit -m "feat: 添加新功能"

# 4. 推送到远程
git push origin feature/new-feature

# 5. 创建Pull Request（如果使用GitHub/GitLab）
```

### 发布流程

```bash
# 1. 从develop创建release分支
git checkout develop
git checkout -b release/v1.0.0

# 2. 修复bug，准备发布
# ... 修复 ...

# 3. 合并到main和develop
git checkout main
git merge release/v1.0.0
git tag v1.0.0

git checkout develop
git merge release/v1.0.0
```

## 📦 版本号规范

### 语义化版本 (SemVer)

格式: `MAJOR.MINOR.PATCH`

- **MAJOR**: 不兼容的API修改
- **MINOR**: 向后兼容的功能新增
- **PATCH**: 向后兼容的Bug修复

### 示例

- `v1.0.0` - 初始版本
- `v1.1.0` - 新增功能（数据库V2）
- `v1.1.1` - Bug修复
- `v2.0.0` - 重大更新（不兼容）

## 🔒 敏感信息处理

- API密钥

- 交易账户信息
- 个人对话记录（包含敏感信息）

