# Quant Research Engineer 差距与路线图

## 差距对照（摘要）
- 研究归因：缺少 Top-3~5 因子归因报告、证据链与置信度量化。
- 因子库：多源因子未统一注册、版本化与质量管理。
- 稳健性验证：缺少标准化 OOS / Walk-forward 与偏差检查流程。
- 执行系统：缺少完整 OMS/风控状态机/幂等/回放(event-sourcing)。
- 可验证调用：关键调用缺少统一 ok/err + reason + evidence 输出。

## 路线图（优先级）
1) 研究可复现流水线
2) Edge Attribution 模块
3) 因子库与版本管理
4) 稳健性验证体系
5) 执行层最小闭环
6) 可验证工具调用协议

## 详细实施计划

### Phase 1：研究流水线与 OOS 规范化（1-2 周）
目标：建立可重复、可审核的研究管线。
- 统一数据切片、特征工程、训练/验证/回测输入输出结构
- 提供 run config（数据窗口、特征版本、模型/规则版本）
- 输出标准化报告（含参数、样本、性能指标、置信区间）

交付物：
- 标准化研究脚本入口与配置样例
- OOS / Walk-forward 报告模板
- 运行日志与数据版本签名

### Phase 2：Edge Attribution（2-3 周）
目标：解释收益来源，支持 Top-3~5 稀疏归因。
- 因子贡献度：稀疏线性/SHAP 二选一（优先稀疏线性）
- 证据链：对应行情窗口与特征值快照
- 置信度：交叉验证稳定性或置信区间

交付物：
- attribution report（因子贡献、证据、置信度）
- 归因回放脚本与复核指标

### Phase 3：因子库与版本化（2 周）
目标：多源因子标准化、可追踪。
- 因子注册表：name/version/source/frequency/quality
- 因子存储：多源对齐、缺失处理、异常检测
- 版本冻结：实验与生产隔离

交付物：
- 因子注册表与版本策略
- 因子构建与质量报告脚本

### Phase 4：稳健性验证体系（1-2 周）
目标：避免过拟合与偏差。
- 偏差检查：lookahead / survivorship / selection
- OOS 稳定性：滚动窗口/随机化/回撤压力测试

交付物：
- 稳健性检查报告
- 风险与偏差警报规则

### Phase 5：执行层最小闭环（2-4 周）
目标：能落地的 OMS + 风控 + 回放。
- 订单状态机（pending/partial/filled/cancelled）
- 幂等与重试，失败降级
- event-sourcing 回放（可复盘）

交付物：
- 执行层服务与回放工具
- 风控包络配置与审计日志

### Phase 6：可验证工具调用协议（1 周）
目标：执行与数据调用具备可审计证据。
- 统一输出：ok/err + reason + evidence
- 重要调用强制落库与记录

交付物：
- 统一协议封装
- 调用日志与审计输出

## 依赖与协同建议
- 数据源接入与质量管理需要与数据工程协作
- 执行层与风控需与交易/交易所接入协作
- 研究流水线与归因模块先行，可快速验证价值
