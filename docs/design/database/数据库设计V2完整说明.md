## 📊 数据库表结构

### 每个交易员数据库包含6个表

#### 1. conversations - 对话记录表

**存储内容**:
- 所有对话记录（Discord、微信等）
- 自动提取的交易信息
- 对话上下文

**字段**:
- `timestamp`, `user_message`, `trader_message`
- `source`, `has_trading_info`, `extracted_content`
- `btc_price`, `created_at`, `is_archived`

---

#### 2. trade_records - 交易记录表

**存储内容**:
- 交易截图信息（`screenshot_path`）
- 文本交易记录（`text_content`）
- 手工录入的交易记录

**字段**:
- `timestamp`, `symbol`, `direction`, `leverage`
- `entry_price`, `exit_price`, `profit_pct`, `profit_usdt`
- `strategy`, `screenshot_path`, `text_content`, `source`

**支持方式**:
- ✅ **截图方式**: 保存截图文件，路径存储在 `screenshot_path`
- ✅ **文本方式**: 内容存储在 `text_content`
- ✅ **手工录入**: 通过API或脚本录入

---

#### 3. trader_viewpoints - 交易观点表

**存储内容**:
- 从对话中提取的观点
- 从交易记录中提取的策略
- 手工录入的观点

**字段**:
- `content`, `timestamp`, `source`, `category`, `tags`
- `btc_price`, `related_trade_id`, `related_conversation_id`

---

#### 4. trading_signals - 交易信号表

**存储内容**:
- 系统生成的所有交易信号
- 信号的所有参数（入场、止损、止盈等）
- 信号状态（pending/completed/stopped/missed）

**字段**:
- `signal_time`, `timeframe`, `signal_type`
- `entry_price`, `stop_loss`, `take_profit_1`, `take_profit_2`
- `entry_model`, `strength`, `risk_reward_ratio`
- `volatility_level`, `system_name`, `status`

---

#### 5. signal_evaluations - 信号评估表

**存储内容**:
- 信号的评估结果
- 实际交易数据
- 评估备注

**字段**:
- `signal_id` (外键关联trading_signals)
- `evaluation_time`, `result`
- `actual_entry_price`, `actual_exit_price`
- `actual_profit_pct`, `actual_profit_usdt`
- `stop_loss_hit`, `take_profit_1_hit`, `take_profit_2_hit`
- `missed`, `notes`

**工作流程**:
1. 系统生成信号 → 保存到 `trading_signals` 表（status='pending'）
2. 信号执行后 → 保存评估到 `signal_evaluations` 表
3. 更新信号状态 → `trading_signals.status` 更新为 completed/stopped/missed

---

#### 6. strategy_rules - 策略规则表（可选）

**存储内容**:
- 策略配置参数
- 规则配置
- 规则开关

**字段**:
- `rule_name`, `rule_type`, `rule_content`, `parameters`
- `enabled`, `created_at`, `updated_at`

---

## 🔄 策略和规则引擎

### 方案对比

#### 方案1: 规则引擎自己管理（推荐核心规则）

**优势**:
- ✅ 更灵活，可以动态加载
- ✅ 不需要数据库依赖
- ✅ 规则逻辑在代码中，易于维护
- ✅ 可以版本控制

**适用**:
- 核心交易规则（Vegas通道、VWAP等）
- 信号生成逻辑
- 复杂的规则判断

#### 方案2: 存储在数据库（推荐配置参数）

**优势**:
- ✅ 可以查询和统计
- ✅ 可以动态修改
- ✅ 可以跨系统共享

**适用**:
- 策略配置参数（EMA周期、止损比例等）
- 规则开关（启用/禁用某个规则）
- 简单的规则配置

#### 方案3: 混合使用（推荐）⭐

**核心规则**: 在代码中（规则引擎自己管理）
**配置参数**: 在数据库中（strategy_rules表）

**示例**:
```python
# 核心规则在代码中
def check_vegas_entry(klines):
    # Vegas通道判断逻辑
    ema144 = calculate_ema(klines, 144)
    ema169 = calculate_ema(klines, 169)
    # ... 规则逻辑
    
# 配置参数在数据库中
config = db.get_strategy_rule('vegas_entry')
ema_period_144 = config['parameters']['ema_144']
ema_period_169 = config['parameters']['ema_169']
```

**建议**:
- ✅ 核心规则逻辑 → 代码中（规则引擎管理）
- ✅ 配置参数 → 数据库中（strategy_rules表）
- ✅ 规则开关 → 数据库中（enabled字段）

## 🔍 如何查询数据库

### 方式1: 使用标准SQL（推荐）

DuckDB支持**标准SQL语法**，可以直接使用SQL查询：

```sql
-- 连接De.的数据库
ATTACH 'data/qingniao_de.duckdb' AS de_db;

-- 查询最近10条观点
SELECT 
    timestamp,
    content,
    category,
    btc_price
FROM de_db.trader_viewpoints
ORDER BY timestamp DESC
LIMIT 10;

-- 查询交易记录
SELECT 
    timestamp,
    direction,
    entry_price,
    profit_pct
FROM de_db.trade_records
ORDER BY timestamp DESC;

-- 查询交易信号
SELECT 
    signal_time,
    signal_type,
    entry_price,
    status
FROM de_db.trading_signals
WHERE status = 'pending'
ORDER BY signal_time DESC;

-- 查询信号评估结果
SELECT 
    s.signal_time,
    s.signal_type,
    e.result,
    e.actual_profit_pct
FROM de_db.trading_signals s
LEFT JOIN de_db.signal_evaluations e ON s.id = e.signal_id
ORDER BY s.signal_time DESC;
```

### 方式2: 使用Python API

```python
from db_manager_trader import TraderDBManager

# 查询De.的观点
db = TraderDBManager('de')
viewpoints = db.get_viewpoints(limit=10)

# 查询交易信号
signals = db.get_trading_signals(status='pending', limit=10)

db.close()
```

### 方式3: 使用DuckDB Python API

```python
import duckdb

# 直接连接数据库
conn = duckdb.connect('src/data/qingniao_de.duckdb')

# 执行SQL查询
result = conn.execute('''
    SELECT * FROM trader_viewpoints
    ORDER BY timestamp DESC
    LIMIT 10
''').fetchall()

for row in result:
    print(row)

conn.close()
```

## 📊 查询示例

### 常用查询场景

#### 1. 查询De.的所有观点

```sql
SELECT * FROM trader_viewpoints
ORDER BY timestamp DESC;
```

#### 2. 查询盈利的交易记录

```sql
SELECT * FROM trade_records
WHERE profit_pct > 0
ORDER BY profit_pct DESC;
```

#### 3. 查询待评估的信号

```sql
SELECT * FROM trading_signals
WHERE status = 'pending'
ORDER BY signal_time DESC;
```

#### 4. 查询信号评估统计

```sql
SELECT 
    result,
    COUNT(*) as count,
    AVG(actual_profit_pct) as avg_profit
FROM signal_evaluations
GROUP BY result;
```

#### 5. 跨表关联查询

```sql
-- 查询观点及其关联的交易记录
SELECT 
    v.timestamp,
    v.content,
    t.profit_pct
FROM trader_viewpoints v
LEFT JOIN trade_records t ON v.related_trade_id = t.id
WHERE v.category = 'trading';
```
