# 数据库设计 V2 说明

## 🎯 设计原则

### 1. 按交易员分库

**每个交易员独立的数据库**:
- `qingniao_de.duckdb` - De.的数据库
- `qingniao_meng.duckdb` - 梦的数据库
- 未来可以添加更多交易员

**优势**:
- ✅ 数据隔离，互不影响
- ✅ 易于管理和备份
- ✅ 可以独立优化
- ✅ 易于扩展

---

## 📊 数据库结构

### 每个交易员数据库包含的表

#### 1. conversations - 对话记录表

**用途**: 存储交易员的对话记录

**字段**:
- `id` - 主键
- `timestamp` - 对话时间（北京时间）
- `user_message` - 用户消息
- `trader_message` - 交易员消息
- `source` - 来源（discord/wechat/manual）
- `has_trading_info` - 是否包含交易信息
- `extracted_content` - 提取的交易内容
- `btc_price` - 当时的BTC价格
- `created_at` - 创建时间
- `is_archived` - 是否已归档

**适合存储**:
- ✅ 所有对话记录
- ✅ 自动提取的交易信息
- ✅ 对话上下文

---

#### 2. trade_records - 交易记录表

**用途**: 存储交易员的交易记录

**字段**:
- `id` - 主键
- `timestamp` - 交易时间
- `symbol` - 交易对（默认BTC/USDT）
- `direction` - 方向（long/short）
- `leverage` - 杠杆倍数
- `entry_price` - 开仓价格
- `exit_price` - 平仓价格
- `profit_pct` - 收益率（%）
- `profit_usdt` - 盈利金额（USDT）
- `strategy` - 交易策略
- `screenshot_path` - 截图路径（如果来自截图）
- `text_content` - 文本内容（如果来自文本）
- `source` - 来源（manual/screenshot/text）
- `created_at` - 创建时间
- `is_archived` - 是否已归档

**适合存储**:
- ✅ 交易截图信息
- ✅ 文本交易记录
- ✅ 手工录入的交易记录

---

#### 3. trader_viewpoints - 交易观点表

**用途**: 存储从对话和交易记录中提取的交易观点

**字段**:
- `id` - 主键
- `content` - 观点内容
- `timestamp` - 观点时间
- `source` - 来源（conversation/trade_record/manual）
- `category` - 类别（trading/analysis/instruction/theory）
- `tags` - 标签（JSON格式）
- `btc_price` - 当时的BTC价格
- `related_trade_id` - 关联的交易记录ID
- `related_conversation_id` - 关联的对话ID
- `created_at` - 创建时间
- `updated_at` - 更新时间
- `is_archived` - 是否已归档

**适合存储**:
- ✅ 从对话中提取的观点
- ✅ 从交易记录中提取的策略
- ✅ 手工录入的观点

---

#### 4. trading_signals - 交易信号表

**用途**: 存储系统生成的交易信号

**字段**:
- `id` - 主键
- `signal_time` - 信号生成时间
- `timeframe` - 时间框架（5m/15m/1h）
- `signal_type` - 信号类型（long/short）
- `entry_price` - 入场价格
- `stop_loss` - 止损价格
- `take_profit_1` - 第一止盈价格
- `take_profit_2` - 第二止盈价格
- `entry_model` - 入场模型（Vegas/VWAP/Pinbar等）
- `strength` - 信号强度（strong/medium/weak）
- `risk_reward_ratio` - 盈亏比
- `volatility_level` - 波动率水平
- `system_name` - 系统名称（De./梦等）
- `status` - 状态（pending/completed/stopped/missed）
- `created_at` - 创建时间
- `updated_at` - 更新时间

**适合存储**:
- ✅ 系统生成的所有交易信号
- ✅ 信号的所有参数
- ✅ 信号状态

---

#### 5. signal_evaluations - 信号评估表

**用途**: 存储信号的评估结果

**字段**:
- `id` - 主键
- `signal_id` - 关联的信号ID（外键）
- `evaluation_time` - 评估时间
- `result` - 评估结果（completed/stopped/missed）
- `actual_entry_price` - 实际入场价格
- `actual_exit_price` - 实际出场价格
- `actual_profit_pct` - 实际收益率
- `actual_profit_usdt` - 实际盈利金额
- `stop_loss_hit` - 是否触发止损（0/1）
- `take_profit_1_hit` - 是否触发第一止盈（0/1）
- `take_profit_2_hit` - 是否触发第二止盈（0/1）
- `missed` - 是否错过（0/1）
- `notes` - 备注
- `created_at` - 创建时间

**适合存储**:
- ✅ 信号的评估结果
- ✅ 实际交易数据
- ✅ 评估备注

---

#### 6. strategy_rules - 策略规则表（可选）

**用途**: 存储策略配置和规则

**字段**:
- `id` - 主键
- `rule_name` - 规则名称
- `rule_type` - 规则类型
- `rule_content` - 规则内容（JSON格式）
- `parameters` - 参数（JSON格式）
- `enabled` - 是否启用（0/1）
- `created_at` - 创建时间
- `updated_at` - 更新时间

**适合存储**:
- ✅ 策略配置参数
- ✅ 规则配置
- ⚠️ 核心规则逻辑建议在代码中

---

## 🔄 策略和规则引擎

### 方案对比

#### 方案1: 规则引擎自己管理（推荐）

**优势**:
- ✅ 更灵活，可以动态加载
- ✅ 不需要数据库依赖
- ✅ 规则逻辑在代码中，易于维护
- ✅ 可以版本控制

**适用场景**:
- 核心交易规则
- 信号生成逻辑
- 复杂的规则判断

#### 方案2: 存储在数据库

**优势**:
- ✅ 可以查询和统计
- ✅ 可以动态修改
- ✅ 可以跨系统共享

**适用场景**:
- 策略配置参数
- 规则开关
- 简单的规则配置

#### 方案3: 混合使用（推荐）

**核心规则**: 在代码中（规则引擎自己管理）
**配置参数**: 在数据库中（strategy_rules表）

**示例**:
```python
# 核心规则在代码中
def check_vegas_entry(klines):
    # 规则逻辑
    pass

# 配置参数在数据库中
config = db.get_strategy_rule('vegas_entry')
ema_period = config['parameters']['ema_period']
```

## 📁 数据存储建议

### 对话记录

**存储方式**:
- ✅ 存储在 `conversations` 表
- ✅ 自动提取交易信息到 `trader_viewpoints` 表
- ✅ 保留原始对话记录

### 交易记录

**存储方式**:
- ✅ 截图: 保存截图文件，路径存储在 `screenshot_path`
- ✅ 文本: 内容存储在 `text_content`
- ✅ 自动提取观点到 `trader_viewpoints` 表

### 交易信号

**存储方式**:
- ✅ 系统生成信号时，自动保存到 `trading_signals` 表
- ✅ 信号评估时，保存到 `signal_evaluations` 表
- ✅ 更新信号状态

## 🔍 查询方式

### 使用SQL（标准SQL语法）

DuckDB支持标准SQL语法，可以直接使用SQL查询：

```sql
-- 查询De.的观点
SELECT * FROM trader_viewpoints
WHERE category = 'trading'
ORDER BY timestamp DESC
LIMIT 10;
```

### 使用Python API

```python
from db_manager_trader import TraderDBManager

db = TraderDBManager('de')
viewpoints = db.get_viewpoints(limit=10)
```

### 使用DuckDB Python API

```python
import duckdb

conn = duckdb.connect('src/data/qingniao_de.duckdb')
result = conn.execute('SELECT * FROM trader_viewpoints').fetchall()
```
