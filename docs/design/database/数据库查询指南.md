# 数据库查询指南

## 📊 数据库结构

### 按交易员分库

每个交易员有独立的数据库：
- `qingniao_de.duckdb` - De.的数据库
- `qingniao_meng.duckdb` - 梦的数据库
- `qingniao_shared.duckdb` - 共享数据库（交易员信息）

### 每个交易员数据库包含的表

1. **conversations** - 对话记录表
2. **trade_records** - 交易记录表
3. **trader_viewpoints** - 交易观点表
4. **trading_signals** - 交易信号表
5. **signal_evaluations** - 信号评估表
6. **strategy_rules** - 策略规则表（可选）

## 🔍 SQL查询示例

### 1. 查询De.的观点

```sql
-- 连接De.的数据库
ATTACH 'data/qingniao_de.duckdb' AS de_db;

-- 查询最近10条观点
SELECT 
    timestamp,
    content,
    category,
    btc_price
FROM de_db.trader_viewpoints
ORDER BY timestamp DESC
LIMIT 10;
```

### 2. 查询交易记录

```sql
-- 查询De.的所有交易记录
SELECT 
    timestamp,
    symbol,
    direction,
    entry_price,
    exit_price,
    profit_pct,
    profit_usdt
FROM de_db.trade_records
ORDER BY timestamp DESC;
```

### 3. 查询交易信号

```sql
-- 查询待评估的信号
SELECT 
    id,
    signal_time,
    timeframe,
    signal_type,
    entry_price,
    stop_loss,
    take_profit_1,
    status
FROM de_db.trading_signals
WHERE status = 'pending'
ORDER BY signal_time DESC;
```

### 4. 查询信号评估结果

```sql
-- 查询信号及其评估结果
SELECT 
    s.id,
    s.signal_time,
    s.signal_type,
    s.entry_price,
    e.result,
    e.actual_profit_pct,
    e.stop_loss_hit,
    e.take_profit_1_hit
FROM de_db.trading_signals s
LEFT JOIN de_db.signal_evaluations e ON s.id = e.signal_id
ORDER BY s.signal_time DESC;
```

### 5. 统计查询

```sql
-- 统计De.的交易记录
SELECT 
    direction,
    COUNT(*) as count,
    AVG(profit_pct) as avg_profit_pct,
    SUM(profit_usdt) as total_profit
FROM de_db.trade_records
GROUP BY direction;
```

### 6. 跨表关联查询

```sql
-- 查询观点及其关联的交易记录
SELECT 
    v.timestamp,
    v.content,
    t.entry_price,
    t.profit_pct
FROM de_db.trader_viewpoints v
LEFT JOIN de_db.trade_records t ON v.related_trade_id = t.id
WHERE v.category = 'trading'
ORDER BY v.timestamp DESC;
```

## 🐍 Python查询示例

### 使用DuckDB Python API

```python
import duckdb
from pathlib import Path

# 连接数据库
db_file = Path("src/data/qingniao_de.duckdb")
conn = duckdb.connect(str(db_file))

# 查询观点
result = conn.execute('''
    SELECT * FROM trader_viewpoints
    ORDER BY timestamp DESC
    LIMIT 10
''').fetchall()

for row in result:
    print(row)

conn.close()
```

## 📊 常用查询场景

### 1. 查询特定时间段的观点

```sql
SELECT * FROM trader_viewpoints
WHERE timestamp >= '2025-12-24 00:00:00'
  AND timestamp <= '2025-12-24 23:59:59'
ORDER BY timestamp;
```

### 2. 查询盈利的交易记录

```sql
SELECT * FROM trade_records
WHERE profit_pct > 0
ORDER BY profit_pct DESC;
```

### 3. 查询已评估的信号

```sql
SELECT 
    s.*,
    e.result,
    e.actual_profit_pct
FROM trading_signals s
JOIN signal_evaluations e ON s.id = e.signal_id
WHERE s.status != 'pending';
```

### 4. 查询特定类别的观点

```sql
SELECT * FROM trader_viewpoints
WHERE category = 'trading'
ORDER BY timestamp DESC;
```

### 5. 查询包含特定标签的观点

```sql
-- 注意：tags是JSON格式，需要解析
SELECT * FROM trader_viewpoints
WHERE tags LIKE '%挂单%'
ORDER BY timestamp DESC;
```

## 🔧 高级查询

### 1. 使用DuckDB的JSON函数

```sql
-- 查询包含特定标签的观点
SELECT 
    id,
    timestamp,
    content,
    json_extract_string(tags, '$[0]') as first_tag
FROM trader_viewpoints
WHERE tags IS NOT NULL;
```

### 2. 时间聚合查询

```sql
-- 按日期统计交易记录
SELECT 
    DATE(timestamp) as date,
    COUNT(*) as trade_count,
    AVG(profit_pct) as avg_profit
FROM trade_records
GROUP BY DATE(timestamp)
ORDER BY date DESC;
```

### 3. 窗口函数查询

```sql
-- 计算累计盈亏
SELECT 
    timestamp,
    profit_usdt,
    SUM(profit_usdt) OVER (ORDER BY timestamp) as cumulative_profit
FROM trade_records
ORDER BY timestamp;
```

## 💡 查询最佳实践

### 1. 使用索引

所有时间戳字段都已创建索引，查询时尽量使用时间范围：

```sql
-- 好的查询（使用索引）
SELECT * FROM trader_viewpoints
WHERE timestamp >= '2025-12-24 00:00:00'
  AND timestamp <= '2025-12-24 23:59:59';

-- 避免全表扫描
SELECT * FROM trader_viewpoints
WHERE content LIKE '%某个词%';  -- 这个会全表扫描
```

### 2. 限制结果数量

```sql
-- 总是使用LIMIT
SELECT * FROM trader_viewpoints
ORDER BY timestamp DESC
LIMIT 100;
```

### 3. 使用连接查询

```sql
-- 使用JOIN而不是子查询
SELECT 
    v.*,
    t.profit_pct
FROM trader_viewpoints v
LEFT JOIN trade_records t ON v.related_trade_id = t.id;
```

## 📝 策略和规则引擎

### 策略规则表（可选）

策略规则可以存储在数据库中，也可以由规则引擎自己管理。

**存储在数据库的优势**:
- ✅ 可以查询和统计
- ✅ 可以版本管理
- ✅ 可以跨系统共享

**规则引擎自己管理的优势**:
- ✅ 更灵活
- ✅ 不需要数据库依赖
- ✅ 可以动态加载

**建议**:
- 如果规则需要查询和统计，存储在数据库
- 如果规则是代码逻辑，由规则引擎自己管理
- 可以混合使用：核心规则在代码中，配置参数在数据库中
