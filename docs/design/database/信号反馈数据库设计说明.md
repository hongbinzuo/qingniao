# 信号反馈数据库设计说明

## 数据库设计

### 1. trading_signals 表（扩展）

**用途**: 存储所有交易信号及其状态反馈信息

**核心字段**:
- `id` - 主键
- `signal_time` - 信号生成时间
- `timeframe` - 时间框架（5m/15m）
- `symbol` - 币种（BTC, ETH等）
- `signal_type` - 方向（long/short）
- `entry_price` - 入场价
- `stop_loss` - 止损价
- `take_profit_1` - 第一止盈价
- `take_profit_2` - 第二止盈价
- `system_name` - 系统名称（abu/de等）
- `status` - 状态（pending/active/completed/stopped/missed）

**信号反馈扩展字段**:
- `entry_time` - 实际入场时间
- `exit_time` - 退出时间
- `exit_price` - 退出价格
- `exit_reason` - 退出原因
- `pnl_pct` - 盈亏百分比
- `breakeven_stop_set` - 是否已设置保本止损（0/1）
- `quick_tp_reached` - 是否达到0.5%快速止盈（0/1）
- `last_check_time` - 最后检查时间
- `check_count` - 检查次数
- `entry_price_actual` - 实际入场价格

### 2. signal_evaluations 表

**用途**: 存储信号的评估结果（当信号结束时）

**字段**:
- `id` - 主键
- `signal_id` - 关联信号ID（外键）
- `evaluation_time` - 评估时间
- `result` - 结果（completed/stopped/missed）
- `actual_entry_price` - 实际入场价
- `actual_exit_price` - 实际退出价
- `actual_profit_pct` - 实际收益率
- `actual_profit_usdt` - 实际盈利金额
- `stop_loss_hit` - 是否触发止损（0/1）
- `take_profit_1_hit` - 是否触发第一止盈（0/1）
- `take_profit_2_hit` - 是否触发第二止盈（0/1）
- `missed` - 是否错过（0/1）
- `notes` - 备注

## 状态映射

### 内部状态 → 数据库状态

| 内部状态 | 数据库状态 | 说明 |
|---------|-----------|------|
| pending | pending | 待激活 |
| active | active | 交易中 |
| partial_tp | active | 部分止盈（仍活跃） |
| quick_tp | completed | 快速止盈（完成） |
| full_tp | completed | 全部止盈（完成） |
| stopped | stopped | 已止损 |
| expired | missed | 已过期 |

## 数据维护

### 1. 自动维护

系统会自动维护数据：
- **添加信号**: 生成信号时自动添加到数据库
- **更新状态**: 每1分钟检查时自动更新状态
- **保存评估**: 信号结束时自动保存评估结果

### 2. 数据查询

#### 查询活跃信号
```python
from db_manager_trader import TraderDBManager

db = TraderDBManager(trader_id='abu')
# 查询待激活信号
pending_signals = db.get_trading_signals(status='pending', system_name='abu')

active_signals = db.get_trading_signals(status='active', system_name='abu')
```

#### 查询历史信号
```python
# 查询已完成的信号
completed_signals = db.get_trading_signals(status='completed', system_name='abu', limit=100)

```

#### 清理过期信号
```python
# 清理超过7天的已完成信号（可选）
conn = db._get_connection()
conn.execute('''
    DELETE FROM trading_signals 
    WHERE status IN ('completed', 'stopped', 'missed')
    AND created_at < datetime('now', '-7 days')
''')
conn.commit()
```

## 性能优化

### 索引

已创建的索引：
- `idx_trading_signals_signal_time` - 信号时间索引
- `idx_trading_signals_status` - 状态索引

建议添加的索引：
```sql
CREATE INDEX IF NOT EXISTS idx_trading_signals_system_status 
ON trading_signals(system_name, status);

CREATE INDEX IF NOT EXISTS idx_trading_signals_symbol_timeframe 
ON trading_signals(symbol, timeframe);
```

### 查询优化

1. **使用索引字段查询**: 优先使用 `status`, `system_name`, `signal_time` 查询
2. **限制结果数量**: 使用 `limit` 参数限制返回数量
3. **定期清理**: 定期清理已完成的历史数据

## 数据一致性

### 事务保证

- 所有数据库操作都在事务中执行
- 更新信号状态和保存评估结果是原子操作

### 数据同步

- 数据库是主存储
- JSON文件作为备份，每1分钟同步一次
- 如果数据库不可用，自动降级到JSON文件

## 故障恢复

2. 重新初始化数据库
